# 거래정리 코드 검증 내역

검증일: 2026년 10월 12일

## 사용한 자료와 적용 범위

최신 업로드 `Report(1).zip`을 기준으로 10월 6일의 `거래내역_기간필터_수정본.zip` 중 `report_paths.py`, `SumTradeList.py`, `test_workflow.py`를 연결하고 승인된 문제를 보완했다. 최신 ZIP의 `contract_report_list.py`를 유지하며 연장 추정과 기간 기록을 수정했다.

변경한 실행 파일은 `Scripts/contract_report_list.py`, `Scripts/report_paths.py`, `Scripts/SumTradeList.py`, `Scripts/SumAP.py`, `run.py`이다. 증권사별 거래·AP normalizer 및 `tax_refunds.py`의 계산식은 수정 전과 바이트 단위로 같다.

## 수정한 동작

1. 계약 결과를 상품명·이름·계좌번호·보고서작성시작일·보고서작성마감일의 5열로 연결한다. 거래는 해당 고객의 기간 안에서 양 끝 날짜를 포함한다.
2. 같은 계좌의 여러 작성기간을 보존한다. 거래일에 해당하는 상품을 선택하며, 서로 다른 상품이 동일 거래일에 겹치면 중단한다.
3. AP는 보고서 종료일에 해당하는 상품을 우선 선택한다. 분기 중 종료 계약은 기존 취합 범위를 유지하되 가장 최근 작성기간의 상품을 쓰고 기준일 검토를 남긴다. AP 원본의 잔고 날짜를 자동 검증하는 기능은 없다.
4. 실제 이전 계약행이 있을 때 명시적 해지·만기 후 공백을 연장 추정으로 채우지 않는다. 직전 계약행이 없는 첫 연장행의 추정은 유지한다. 추정 및 생략 내역은 로그에 남긴다.
5. 계약 결과의 숨김 메타데이터에 전체 생성 기간을 기록하고 취합 시 현재 설정과 비교한다. 시작일만 변경하거나 기간을 넓혀도 재추출을 요구한다. 기록이 없는 구버전 결과도 재추출한다.
6. 이번 실제 실행에서 환율 부재로 계산 실패가 발견되어, `검토필요`의 계산 실패 행이 있으면 거래 정리 메뉴·전체 실행을 중단하고 최종 거래 취합도 차단한다. 규칙 미지정 경고는 기존처럼 검토 대상으로 남는다.

## 회귀 검사

`python -m unittest discover -s Tests -v`의 25개 테스트가 모두 통과했다. 경계 사례는 합성 입력으로 확인했으며 실제 3분기 거래금액의 대사를 대신하지 않는다.

- 보고서 시작일·마감일 포함, 분기 전 해지·분기 후 가입 제외.
- 분기 중 신규가입과 해지, 같은 상품 재가입의 공백, 상태가 연장인 재가입.
- 정상 연속 연장, 이전 이력 없는 연장 추정, 미래 연장행에 적힌 과거 해지일.
- 계약 결과의 생성 기간 불일치, 구형 4열, 메타데이터 없음, 결과 행의 기간 이탈 차단.
- AP의 행 순서와 무관한 상품 선택, 기간 중 종료 계약의 검토 표시, 상품 충돌 차단.
- 원화·USD·JPY 세금환급 부호와 원본 환율 우선순위, 환급 취소·재징수 구분.
- 거래파일 검색·동일 이름 확장자 충돌, 계산 실패 차단 및 규칙 미지정 검토 유지.

## AP 매칭 변경 검증

새 계약기간 목록과 동일한 AP 정리 결과를 고정해, 수정 전/후 `SumAP.py`의 상품 선택 로직을 비교했다. 12행의 상품만 테크차이나에서 글로벌임펄스로 변경되었고, 그 외 모든 열은 행별로 같았다. 잔고·수량·취득단가·매입액·시가 및 투자비중을 바꾸지 않았다.

| 현재 첨부 AP의 검증 실행 | 수 |
|---|---:|
| 전체_내림차순 | 1,382행 |
| 10%초과 | 401행 |
| 미매칭 제외 행 | 23행 |
| 계약목록에 있으나 AP에서 못 찾은 계좌·이름 | 17개 |
| 분기 중 종료로 기준일 확인이 필요한 계약 | 21개 |
| 해당 종료 계약 중 실제 AP에 매칭된 잔고 | 8행 |

이는 현재 첨부 파일과 현재 환율 설정으로 실행한 결과다. AP 원본의 잔고 기준일이 각 고객의 보고 마감일에 맞는지까지 확정한 수치는 아니다. 이전 10월 1일 검증 문서의 행 수는 당시 자료 기준이므로 현재 수치와 구분한다. `ap_exchange_date`는 null로 유지했으며 KB·삼성 AP는 파일 내 최신 환율을 사용하는 기존 동작이다.

## 거래 원본과 환율의 기간 불일치

현재 설정은 3분기지만 거래 원본 11,800행의 날짜는 2026년 4~6월이다. 첨부된 통화별 환율 파일은 7~9월 자료라 거래일 이전 환율이 없다.

| 증권사 | 거래 원본 행 | 환율 계산 실패 | 규칙 미지정 |
|---|---:|---:|---:|
| 삼성 | 10,061 | 6,880 | 0 |
| 한투 | 564 | 62 | 1 |
| KB | 571 | 412 | 0 |
| 교보 | 541 | 517 | 0 |
| 메리츠 | 63 | 57 | 0 |
| 합계 | 11,800 | 7,928 | 1 |

차단 추가 전의 진단 실행은 마지막 단계까지 진행되었으나 3분기 기간 필터를 통과하는 거래는 0행이었다. 이를 정상 거래금액 검증으로 보지 않았다. 차단을 추가한 뒤 같은 원본으로 `python run.py all`을 다시 실행하여 거래 정리 후 오류로 중단되는 것과 최종 Excel이 만들어지지 않는 것을 확인했다.

한투의 별도 1건은 기존 `HTS자문사외화실시간직접매수환전` 규칙 미지정이다. 이 경고는 이번 변경에서도 유지했다.

3분기 작업에는 3분기 거래 원본과 거래일에 대응하는 환율, 고객별 마감일에 맞는 AP를 준비해야 한다. 2분기를 작업하려면 기간뿐 아니라 환율·AP도 2분기에 맞춰야 한다. 미래 환율로 과거 거래를 임의 계산하거나 날짜를 바꾸지 않았다.

## 검증 환경과 범위

Linux Python 환경에서 테스트와 실제 스크립트를 실행했다. Windows 배치파일은 명령 구성을 점검했으며 더블클릭 실행을 직접 시험하지 않았다. 메리츠 AP 자동화와 고객별 PDF/Word 보고서 생성은 기존 범위 밖이다. 안내서 Word는 7쪽으로 렌더링하여 표·글자·쪽 나눔을 확인했다.
