# 검증 내역과 변경사항

검증 자료: 첨부된 2026년 2분기 원본. Python 3.12 환경에서 실제 실행했습니다.
Windows 실행하기.bat는 직접 실행하지 못했으며 명령 구성을 점검했습니다.

## 실제 데이터 비교

| 증권사 | 거래 행 | 수정한 환급 행 | 비환급 행 일치 | 경고 |
|---|---:|---:|---:|---:|
| 한투 | 564 | 11 | 553 | 1 |
| KB | 571 | 0 | 571 | 0 |
| 삼성 | 10,061 | 118 | 9,943 | 0 |
| 교보 | 541 | 68 | 473 | 0 |
| 메리츠 | 63 | 0 | 63 | 0 |

거래내역 11,800건 중 환급 197건의 매매금액을 0으로 옮기고, 각종세금을 음수로 변경했습니다.
나머지 11,603건은 변경 전 코드의 재실행 결과와 행별 값이 일치합니다.
원본 환급액이 음수인 경우, 원화·USD·JPY, 이전 날짜 환율 조회, 한투·KB의 원본 환율 우선순위, 추징·재징수·환급 취소 구분을 검사했습니다.
KB·메리츠 원본에는 환급 거래가 없어 해당 증권사는 구성한 입력 사례로 계산식을 검사했습니다.

## AP 비교

| 증권사 | 비교 시트 수 | 값 일치 |
|---|---:|---|
| 한투 | 2 | 일치 |
| KB | 2 | 일치 |
| 교보 | 2 | 일치 |

AP는 같은 원본과 같은 환율 기준으로 기존 코드를 재실행한 결과와 비교했습니다. 최종 AP는 1,459행, 10% 초과 시트는 137행입니다.
Input 15개 파일은 원본과 SHA-256이 모두 같습니다. 계약 추출은 Output 사본에 저장합니다.

## 취합 연결

계약 대상은 133명입니다. SumTradeList.xlsx는 11,058행이며, 계약·기간 필터를 통과한 환급은 190건입니다.
정리 단계의 환급 197건과 최종 취합의 190건 차이는 계약·기간 필터 적용에 따른 것입니다.
최종 취합에서도 환급의 매매금액 0과 각종세금 음수를 확인했습니다.
보고서 시작일·종료일 당일 포함, 종료일 이후 제외, 지정한 계약 대상 시트만 선택하는 동작을 검사했습니다.
파일명 변경, 잠금파일·결과파일 제외, 같은 stem의 확장자 중복으로 발생할 수 있는 덮어쓰기 방지도 검사했습니다.

## 기존 검토 필요 항목

- 한투 거래내역: HTS자문사외화실시간직접매수환전 1건은 규칙 미지정입니다. 원래의 경고와 계산을 유지했습니다.
- 계약 원본 테크차이나 시트 23행과 36행: 해지일이 계약일보다 이른 2건은 기존의 연속 계약 종료일 처리와 경고를 유지했습니다.
- AP: 계약 미매칭으로 제외된 33행과 AP에서 찾지 못한 계약 1건이 있습니다. SumAPLIst.xlsx의 미매칭_검토를 확인합니다.
- 메리츠 AP: 자동 정리 및 취합 기능이 원본 코드에 없으므로 수작업으로 남습니다.

## 경로 외에 정리한 연결 사항

1. 분기명을 코드에 고정하지 않고 각 증권사 Input 폴더의 원본을 읽습니다.
2. 계약 원본은 수정하지 않으며, 결과 사본을 취합 단계에서 읽습니다.
3. 여러 날짜의 계약 대상 시트가 있어도 설정한 보고서 종료일 시트만 선택합니다.
4. 거래 취합에 보고서 종료일 상한을 적용합니다.
5. 메리츠의 기존 파일명 진입점은 v2를 실행하도록 연결했습니다. 변경 전 코드는 Archive/구버전코드에 보관했습니다.
6. AP 최종 파일명은 제공된 기존 파일명 SumAPLIst.xlsx로 통일했습니다.
